# Opinions (global)

My technical opinions and preferences. Agents should weigh these when making
design and implementation decisions. Edit to taste; these are starting points.

## Engineering

- Optimize for long-term maintainability over short-term speed.
- Prefer simple, boring, proven technology over novel/clever solutions.
- Delete code aggressively; less code is less liability.
- Tests are evidence, not decoration. A change without a way to verify it is
  not done.
- Reproduce before you fix; verify before you claim done.

## Code style

- Readability over cleverness. Code is read far more than written.
- Match the surrounding code's conventions over personal preference.
- Small, focused commits with clear messages.

## Tooling

- Terminal-centered workflow: grep, fzf, Neovim, tmux, low visual clutter.
- Reproducible setups (dotfiles, pinned versions) over manual config.
